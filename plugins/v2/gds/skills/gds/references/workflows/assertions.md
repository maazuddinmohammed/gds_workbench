# Assertion Authoring

Assertions persist user-supplied or explicitly documented business evidence. They may describe grain, keys, relationships, transformations, precedence, quality expectations, or unresolved decisions.

Record the statement, scope, evidence/rationale, confidence, and active status using the current dataset schema. Do not promote an agent inference into an Assertion without user confirmation. Assertions inform Analysis, Conceptual, Logical, Dimensional, Mapping, Code, and Validation, but never become executable lineage by themselves.

Loop over the user's stated rules, merge only true duplicates, and mark contradictions blocked for resolution.
