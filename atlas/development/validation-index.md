Run reports do not imply every review row passed. Unexecuted SQL is unexecuted. Existing Python artifacts are preserved; v1 does not generate or execute Python. Native browser directory permissions, zoom and visual appearance need manual verification where browser URL policy prevents automated local-page access.

A modeling-decision sidecar is optional. Absence produces `decision_review_required` (review warning), not a structural failure. Supplied decisions/notes remain checked and hash-bound. This avoids duplicating every modeled definition in a compulsory handoff file.

## Native PowerShell checks

The fallback mirrors these rules in native modules; it does not require Node to validate.

| Check | Native implementation | Regression coverage |
|---|---|---|
| Missing registered Metadata owner | [workspace-native.ps1](../atlas-plugin/scripts/workspace-native.ps1), `Validate-Changes`: error for Model edits that need complete context; warning for context-only reads. Independent Metadata work is unaffected. | `test_workspace.py`, replayed by `test_native_parity.py` |
| Task Snapshot bindings | `Validate-Changes`: verify each declared input, retain it in approval evidence and detect input changes during validation. | Same shared CLI cases |
| Owner key contracts | `Validate-Changes`: compare canonical-key definitions before merging owner datasets, including empty datasets. | Same shared CLI cases |
| Generated SQL | [sql-validation.ps1](../atlas-plugin/scripts/sql-validation.ps1), `Get-AtlasGeneratedCodeIssues`: run statement, projection and relation checks for active new/changed SQL. | `test_native_sql.py`, shared validation/acceptance CLI cases |

SQL checks have the same finite scope as the JavaScript validator. Existing Python artifacts, inactive records and unchanged SQL are preserved. Decision files, SQL evidence queries and Assertions remain optional; existing record, scope and Analysis-count checks run without a decision file.

## Implementation organization

| Code area | Responsibility |
|---|---|
| `validation/run.js` | Common browser/CLI assembly and explicit check coverage. |
| `validation/common.js` | Published schemas, canonical/unique keys, protection and overlay mechanics using `core.js`. |
| `validation/metadata.js` | Metadata references, ownership, table constraints and Object/Attribute locks. |
| `validation/model.js` | Model graph, scope, supports, relationships, Binding and dependent record contracts. |
| `validation/model-policy.js` | Key/audit/naming rules, parent lineage, membership, Binding retarget and default Mapping document structure. |
| `validation/sql.js` | Separate transformation and governed-validation SQL contracts; no execution. |
| `model-quality.js` | Bound decision/evidence checks and modeling-coverage warnings. |
| `workspace.js` / helper | Input files, hashes, evidence/report storage and concurrency checks. |
| `ui/validation.js` | Findings, coverage and navigation; no domain rules. |
| Backend/database | Authoritative authorization, validation and storage constraints. |

Keep cohesive rule families together. Pure validators return bounded structured findings; adapters own files and the UI displays results. Shared serialization remains compatible with the helper, extension and Python. Do not add one file per field or copy rule implementations into workflow/UI files.

Maintain the code index above as checks change: **rule ID, check/reason, code/function, layer, test, status**. Preserve coverage during refactors. Add meaningful valid/invalid cross-record tests, and distinguish automated checks from review guidance and server-only enforcement.
